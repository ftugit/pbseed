## Ключевые места в коде

- `seed.go` — ядро: схема (`ensureSeedSchema` ~:1797), защита полей
  (`protectUsersFields` ~:1675), баны, сессии суперюзера, `seedErr`/`errSeedResponded`.
- `adminplus.go` — «админ+»: `firstAdminRecord`/`firstAdminID`/`isAdminPlus` —
  **одна точка определения для всех исключений первого админа**; новые исключения туда же.
- `automation.go` — хуки: предохранитель `reg_per_day` (потолок 50, встроен во все три
  пути записи конфига) и каскад отзыва сессий при бане.
- `settings.go` — параметры гейтвея (константа сеет только первый запуск; значение в БД
  обязано отличаться от стандарта), эндпоинты `gateway-config`.
- `gatewaycmd.go` — консольная ветка `gateway`.
- `firewall.go`, `gatewayfw.go` — образцы `FindRecordsByFilter`.
- `softdelete.go` — мягкое удаление; `isSoftDeleted` читает `deleted_at` у `users`.
- Таблица `users`: **стоковые поля `created`/`updated`** (формат `2006-01-02 15:04:05.000Z`),
  не `created_at`! `created_at` только у сервисных коллекций. Роль `role` хранится в нижнем
  регистре; есть `banned`, `ban_reason`, `deleted_at`.

## Админ+ (состояние на 2026-09-19)

Первый админ = админ с самой ранней `created` среди живых (разбор по `id`; вычисляется на
лету, при выбытии носителя звание переезжает). Исключения:
1. бан через REST — только суперюзер;
2. смена роли через REST — только суперюзер (закрывает связку «понизить → забанить»);
3. назначение роли `admin` — только админ+ из ролевых админов (суперюзер и консоль выше).
Проверено тестами и живой проверкой 9/9. Кандидаты на будущие исключения (не сделаны):
запрет маскировки на админ+ не-суперюзерам; сужение прав на критичные параметры гейтвея;
консольный бан админ+ только суперюзером; админ+ как управляющий аудит-политиками.
