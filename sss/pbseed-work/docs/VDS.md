# VDS-чеклист (seed-auth deploy-инварианты)

## H3. Трафик — только через прокси (XFF-спуфинг)
`TrustedProxy` доверяет XFF от апстрима. Прямой запрос к контейнеру в обход
прокси = клиент полностью контролирует «свой IP»: подделка `ip_hash`/
`ip_masked`/`history` (обход `kick_on_ip_change` с украденной сессией) и
ключей rate-limit (обход лимитов challenge/login).
- Файрвол: порт приложения доступен ТОЛЬКО с прокси-хоста.
- Прокси: XFF либо append (Envoy/Northflank — берём правый IP), либо set
  (перезапись — ещё строже). Никогда не пробрасывать клиентский XFF как есть.
- Проверка: прямой `curl -H 'X-Forwarded-For: 1.2.3.4' /api/seed/challenge`
  должен упереться в файрвол, а не в приложение.

## Остальные инварианты
- `PB_COOKIE_INSECURE=0` (Secure-cookie; `=1` только локально — сервер
  варнит в лог на буте).
- `SEED_DOMAIN` = публичный хост (подписи привязаны к домену).
- `SEED_IP_KEY` задан (случайные 32+ байт; без него `ip_hash` — plain SHA256).
- `SEED_GEO_ALLOW_PRIVATE` НЕ задан (иначе geo-апдейтер ходит во внутреннюю сеть).
- `pb_hooks`: read-only volume или удалить, если JS-хуки не используются.
- `_superusers.authToken` TTL укоротить; dashboard за MFA/OTP.
- Бэкап включает весь `pb_data` (сессии, tombstones, geo-DB едут на томе).
- Rate limits включены (сервер пишет эффективное состояние в лог на буте).
